# ADR-0004: 再提 core 工具预算 17 → 18（trigger）

- 日期：2026-09-11
- 状态：accepted
- 决策者：架构 owner

## 背景

棘轮在 ADR-0003 后为 17，S6 结束时 **16/17**。

S7 要覆盖“特殊牌效果 / 连锁触发”一类玩法（语料库 `uno`、`spoons`、`kemps`），需要一个新机制：

- `trigger`：把**声明式效果**（摸牌 N 张给某座位、跳过、反向、指定花色）应用到共享状态。

它与现有工具不重叠：`matching` 只管一张牌的匹配与推进，`hidden_draw` 是向对手取牌，`pattern` 是牌型与合法性，`trick` 是墩牌结算。特殊牌效果是“动作之后的后果”，属于另一条轴。

同时需要给 `logic` 增加 `mul` / `mod`：三座位以上的方向与跳过要用 `(current + direction * (1 + skip)) mod players` 表达，这必须在计划里可算，而不是写进 Python。

## 决策

**预算 17 → 18，新增 `trigger` 工具；`logic` 增加 `mul` / `mod`。**

保留约束不变（棘轮只在测试里改、每个工具必须被参考计划使用、契约由解释器强制）。

## 备选方案与为何不选

| 方案 | 优点 | 为何不选 |
|---|---|---|
| 把特殊牌效果写进 `matching.play` | 不新增工具 | 会让 `matching` 依赖具体牌面语义（“2 让下家摸两张”），从机制退化成玩法分叉 |
| 让计划直接用 `state.update` 手写效果 | 零成本 | 摸牌/反向/跳过要维护手牌与牌堆不变量，手写会绕过 `effects` 与守恒检查 |
| 一次提到 20 | 少写 ADR | 预算压力是防膨胀的主要机制 |

## 后果

- 正面：UNO 类特殊牌可表达；方向/跳过在计划里可算；`trigger` 的效果表是纯数据，可被多种玩法复用。
- 负面 / 代价：`trigger` 与 `matching` 存在状态键耦合（`skip` / `direction` / `active_suit`），必须写进契约与文档。
- **强制方式**：轮齿测试（18）、无死工具测试、`tests/test_s7_axes.py` 中对效果顺序与守恒的断言。

## 迁移与删除

不涉及旧路径。
