# ADR-0005: 用 ComposedRulesIR + 确定性降层表达陌生玩法

- 日期：2026-09-12
- 状态：accepted（**实现状态：未实现**，M1 拆操作、M2 落地编译器）
- 决策者：架构 owner

## 背景

G2 的目标是「用户描述一个仓库没有预设、但能用现有机制表达的玩法」，且**新增玩法不新增 IR 家族、Python 计划函数、专属工具、机器人分支或前端分支**。

当前入口是封闭的：`RulesIR = Annotated[ArithmeticIR | WarIR | ... | UnoIR, Field(discriminator="kind")]`，固定 8 个 `kind`。新增玩法只有两条路，都不可接受：

- 加第 9 个 `Literal` 家族 → 模板堆砌，正是工程规范 §9 红线里的「只加不减」；
- 让模型直接提交原始 Plan（`compose_plan(plan=...)`）→ 有太多可微妙出错的地方（漏 `committed`、少 `current_player`、分支不可达），而且**无法从节点图反推意图**，所以「IR 与 Plan 语义不一致」无从校验。

已修复的缺陷恰好证明了第二条路的代价：一个结构合法但语义坏的 plan 让 `betting.legal` 抛裸 `KeyError` 直达 HTTP 500（见 `3ce565a`）。

## 决策

**引入 `ComposedRulesIR`（`kind: composed`，Schema `0.5`），由宿主确定性降层为 `GamePlan`。**

```text
                          ┌─ KnownRulesIR  → 现有 host_compile ─┐
自然语言 → 设计服务/Agent ─┤                                    ├→ GamePlan
                          └─ ComposedRulesIR → 通用编译器 ──────┘
                                                              ↓
                                              同一验证服务 / 同一 Interpreter
```

具体约束：

1. **不要求模型拼接 `call/branch/wait` 节点**，也不向模型注入任何验收玩法的完整模板。模型组合的对象是受约束的**机制声明**。
2. **编译器只按操作类型写降层规则**，不得按游戏标题、game_id 或固定完整描述分派。这是与「查表」的分界线。
3. 两个编译入口是**输入格式差异，不是两套执行器**。同一个 `Interpreter`、同一套工具契约、同一道 playtest 门槛。
4. 一个玩法版本只能绑定**一份 IR、一份编译产物、一个编译来源**；运行时不得自动改用另一份计划。
5. 表达式只允许类型化 AST（字面量、合法字段引用、整数运算、比较、布尔逻辑、有限集合操作）。拒绝 `eval`、自由 Python/JS、反射、动态 import、任意状态路径、递归调用。
6. `generation_source`（`known_parameters | composed_rules`）由**实际编译路径**记录，不能由模型自报。

## 备选方案与为何不选

| 方案 | 优点 | 为何不选 |
|---|---|---|
| 每个新玩法加一个 IR 家族 | 与现状一致，改动最小 | 就是「新增玩法＝新增模板」，G2 的验收目标当场落空 |
| 让模型直接产 Plan（现状 `agent_compose`） | 零编译器成本，表达力最大 | 无裁判、无法反推意图；已验证会产生 500 级缺陷 |
| 通用图/DSL 解释器（任意表达式 + 控制流） | 表达力最高 | 等于引入第二执行面与任意代码，违反单一执行路径与沙箱排除项 |
| 只在提示词里约束模型输出 Plan | 不改架构 | 提示词不是安全约束，§9 明确反对 |
| 直接跳到「模型写代码 + 沙箱」 | 一步到位 | G2 明确排除沙箱；且需要一个可信到能执行模型代码的隔离协议，成本远高于本阶段 |

## 后果

- 正面：新增玩法只需**机制存在**，不需要新模板；验证对象从「一张任意节点图」变成「一份声明式组合」，可做静态检查与 source map。
- 正面：`core/macros.py` 从优化变成**承重结构**——组合里的 `turn` 片段正是宏的位置，`match_turn` 已证明可行。
- 负面 / 代价：需要写并维护一个真正的通用编译器；组合 IR 的语义必须比 8 个家族 IR 更严谨（否则降层会猜测意图）。
- 负面：`GamePlan` Schema 需要升到 `0.5`（见 ADR-0007），带来迁移成本。
- **强制方式**：M2 的编译器不得含按 `game_kind`/标题/id 的分派（形状测试：同一 operation 组合生成同一结构，与游戏名无关）；G2 准出要求 `generation_source=composed_rules` 且编译轨迹证明未调用任何内置玩法计划函数。

## 迁移与删除

- 已知 8 族继续走 `host_compile`，**不迁移**、不改行为。
- `compose_plan(plan=...)` 直接发布能力收窄或删除，见 ADR-0006。
- 旧 `0.4` IR 与存档的兼容/迁移见 ADR-0007。
- 若 M2 完成而 ADR-0006 未落地，视为未完成 —— 两个入口必须同时收紧。
