# ADR-0007: Schema 版本与数据迁移（IR / Plan / 存档）

- 日期：2026-09-12
- 状态：accepted（**实现状态：未实现**，M1/M2 落地）
- 决策者：架构 owner

## 背景

G2 要改三处**已被持久化**的结构：

1. `RulesIR` 增加 `composed` 判别分支；
2. `GamePlan` 增加 `binding_id` 与 `tool_type` 的区分（同一参数化工具的两个实例），并补齐操作的 `config_schema / input_schema / output_schema / reads / writes / feature_constraints`；
3. `SessionStore` 的注册对象升级为 `GameArtifact`（含 `ir_hash`/`plan_hash`/`source_map`/`compiler_version`/`verification_id`）。

现状风险很具体：

- `GamePlan.schema_version` 是 `Literal["0.4"]`，`SessionStore` 存的是 `{plan, playtest, title, fingerprint}`，`core_sessions` 存的是 `serialize()` 出来的引擎状态；
- 本地与用户环境都有已注册的 agent plan（我实测的专用数据目录是干净的 8 族，但用户真实数据目录有 8 条 agent plan，且其中**没有** `fingerprint` 字段——即历史行已经在没有迁移方案的情况下存在了）；
- 计划指纹现在是 `sha256(规范化 plan JSON)[:12]`，一旦 Plan Schema 变化，**同一份逻辑计划会算出不同的哈希**。

如果不处理，会出现两类错误：把迁移后的哈希当作旧验证证据，以及对旧存档静默套用新语义。

## 决策

**Plan Schema 升为 `0.5`，并为 `0.4` 提供显式、可测试的兼容与迁移方案。**

1. **不得改变旧字段含义却继续使用同一 Schema 版本**；`0.4` 与 `0.5` 是两个可区分的版本号。
2. 兼容只放在**入口适配层**：读取 `0.4` 存档时转换到 `0.5` 内存表示；Interpreter 内只有一种标准绑定表示。
3. **迁移后的哈希不得当作旧验证证据。** `plan_hash` 与 `ir_hash` 都是版本敏感的；迁移产生的哈希只能用于「这是同一份内容的哪个版本」，不能用于「这份内容已被验证过」。
4. 旧验证凭据在 IR/宏/编译器/工具契约任一变化后**失效**，必须重新验证（与 ADR-0008 一致）。
5. 兼容层必须有测试：读入 `0.4` 存档 → 转换 → 与迁移前行为一致（同 seed 同动作序列的 trace 相同）。
6. 迁移清单必须显式列出「已修复项」与「剩余项」，不得把 `3ce565a` 的修复与 G2 新工作混为一谈。

## 备选方案与为何不选

| 方案 | 优点 | 为何不选 |
|---|---|---|
| 就地改 `0.4`，不加版本号 | 零迁移成本 | 旧存档含义被静默改变，违反可复现性；这是最危险的一种「省事」 |
| 不兼容，直接要求重新生成 | 实现最简单 | 用户已有对局与已注册玩法全部作废，且无法区分「同一个玩法的哪个版本」 |
| 一次性大版本重写（清库） | 干净 | 单用户 demo 也要保证「刷新/重启可恢复」这条既有承诺 |
| 用 `game_kind` 字符串相等代替哈希绑定 | 简单直观 | 名字相同不代表内容相同；ADR-0005 已明确 `game_id` 是存储身份、`game_kind` 是规则分类，二者不要求相等 |

## 后果

- 正面：版本可区分，旧存档可复现，验证证据不会被嫁接到新产物上。
- 负面 / 代价：需要写迁移代码与迁移测试；`plan_fingerprint` 的语义要重新说明（它是**内容身份**，不是验证凭据）。
- 负面：`SessionStore` 表结构需要迁移（新增列/新表），要做「检查与写入在同一 SQLite 事务 + 唯一键约束」。
- **强制方式**：迁移测试（旧存档转换后行为一致）；反例测试「修改 IR 后复用旧 verification_id → `verification_stale`」；反例测试「迁移后的哈希不得批准注册」。

## 迁移与删除

- 顺序：M1 先完成操作契约与绑定表示（内存结构），M2 完成 IR 分支，M3 完成 artifact 与凭据；迁移脚本随 M3 交付。
- 兼容入口在 M5 消费者迁移完成后删除；删除前必须存在「旧存档 → 新表示」的往返测试。
- 删除判据：仓库内不再存在 `0.4` Plan 的解析路径，且测试只保留一条历史 fixture 作为回归。
