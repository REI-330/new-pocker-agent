# Review 与验收记录

日期：2026-09-07（Asia/Shanghai）。范围：配置、SDK、Agent、DSL、引擎、模拟、运行时、导出、前端状态与既有测试。

## 已修复的根因

| 优先级 | 原问题 | 改动 |
|---|---|---|
| P1 | 获取模型/测试接口直接改写全局配置，尚未保存就影响 Agent | 不可变临时配置；仅保存端点写正式配置 |
| P1 | 保存只存在进程内存，重启丢 Key；前端凭状态文案判断是否有配置 | SQLite + OS keyring；独立 configured/has_key/dirty 状态 |
| P1 | 保存后改模型必须重新输入 Key；换服务可能误发旧 Key | 同地址允许留空复用；换地址要求对应 Key |
| P1 | datalist 过滤当前输入，模型列表看起来只剩一项；更换 Key 留下旧模型 | 完整 select + 手动模式；新 Key/地址清空旧模型选择 |
| P1 | 阶段、轮数、amount 和 scoring 被忽略；胜者可能总是第一人 | 单一规则引擎实现已声明语义、出牌归属、平局和逐轮累计分数 |
| P1 | 没有合法动作但未结束；模拟耗尽步数后伪造完成 | 自动推进阶段或明确结束；模拟上限报错 |
| P1 | 单人模式要求用户替电脑出牌；刷新/重启丢牌局 | 自动电脑回合、SQLite 状态恢复、revision 防重复 |
| P1 | 模型被允许返回任意未实现动作，校验通过但运行失败 | 严格 DSL、完整 JSON Schema、明确能力边界 |
| P1 | 修改规则后仍可使用旧确认、旧模拟和旧试玩 | 新对话使旧确认及派生游戏状态失效 |
| P1 | 用户修改表单后直接发送玩法，实际调用的仍是旧配置 | 草稿修改或配置请求期间暂停发送；提供撤销修改 |
| P1 | 导出只有 JSON，缺乏可玩网页 | 同一 Python 引擎编译有限状态路径 + 本地 HTML/SVG |
| P2 | JSON/HTML 错误、空响应可能变成未处理 500；启动错误静默吞掉 | SDK 统一处理；错误在相应表单和工作台中可见 |
| P2 | SQLite 事务上下文不关闭连接 | 显式关闭连接；保存失败不替换原配置 |

## 实际点击验收

通过真实中转站 https://apipaths.com/v1，使用用户提供的测试 Key。密钥不记录于本文件。

1. 页面填写根域名与 Key，发现 7 个真实模型，选择 gpt-5.4-mini 并保存。
2. 留空 Key 切换到 gpt-5.5 并测试，正式配置仍为 gpt-5.4-mini；再保存后正确更新为 gpt-5.5。
3. 页面刷新恢复模型与 Key 状态；另一个 Python 进程也能恢复系统凭据。
4. 发送简短自然语言比大小描述，真实模型追问牌组、点数顺序和轮数。
5. 在页面回答标准52张、A最大、3轮、每轮1张、胜者1分、平局各1分。
6. 真实模型生成“两人三轮比大小”，页面确认并模拟，产生23个事件，3次round_finished。
7. 点击开始试玩并出牌，电脑自动行动，第1轮进入第2轮。
8. 第2轮刷新浏览器，手牌、分数和轮次恢复；随后重启后端，仍恢复同一牌局和模型配置。
9. 继续第2、3轮，最后显示玩家一2分、电脑1分、“你赢了”。点击再来一局，重新发牌并归零。
10. 页面下载 ZIP，解压包含 index.html、game.json、54张SVG和原始LICENSE。
11. 浏览器工具禁止 file:// 导航，因此用只提供解压文件的本地静态服务器验证同一份离线文件。点击全部3轮，结果和 seed=7 模拟一致（玩家一1分、电脑2分）。网络观察未发现模型/游戏API调用。直接双击 file:// 的打开行为未通过此工具验证。
12. 错误 Key 测试返回明确上游401。测试期间页面被更新为另一把只允许 kimi-k3 的 Key；旧模型测试返回上游503 model_not_found。按新列表选择 kimi-k3 后真实连接通过并保存。之前测试 Key 后来返回401，未将上游授权错误冒充本地故障。
13. 使用已保存的 kimi-k3，从自然语言生成“两人扑克牌游戏”：起手0张、先各摸1张再各出1张、两阶段共2轮。页面确认、模拟、试玩，四次点击正确推进到结算（玩家1分、电脑1分，平局），共22个事件，并成功下载第二个ZIP。
14. 刷新后恢复 kimi-k3 和已结束牌局；修改模型名称时发送按钮禁用，点击“撤销修改”恢复原模型和发送能力，未改写正式配置。此次刷新后的浏览器控制台没有错误。

## 实际限制

- Demo 支持文档声明的规则原语，不能自动实现任意下注、牌型和特殊效果。
- 离线游戏是固定发牌练习局，最多2000个决策节点；超限会明确拒绝。
- 单人、单进程、本机部署；当前电脑为合法动作策略，所有手牌可见。
- 浏览器工具产生的快照可能包含表单内容，因此 .playwright-mcp/ 被忽略，不作为版本库交付物。
